## Context

見 `proposal.md` 的 Why。現況：`docker-compose.yml` 只有 `file-sharing` 一個服務，以 `${HOST_SHARE_PATH:?}:/opt/sharefiles:ro` 掛載；`HOST_SHARE_PATH` 是包含 `SHARE_PREFIX` 子樹的資料根。`docker-compose.dev.yml` 用 `./testdata:/opt/sharefiles:ro` 做本地 fixture。`openspec/specs/file-sharing/spec.md` 要求 web 服務的掛載為 read-only，這點維持不變。

## Goals / Non-Goals

- Goals：Compose 一鍵起 SFTP + Admin UI 容器；與 web 共用同一 Host 目錄；公鑰認證；root-owned chroot；管理者在瀏覽器完成開戶與 key 派發；SFTP 容器可在不重啟下 reconcile 新使用者；新檔案可被 web 非 root process 讀取；dev/CI 可用 fixture 跑通。
- Non-Goals：不改 `file-sharing` 的 hash 規則與 `:ro` 掛載；不做 SFTP 密碼登入、配額、多租戶、WebDAV 等；Admin UI 不做細粒度權限角色（單一管理密碼）；不在 web 服務內嵌 SFTP；不提供每個 SFTP user 的獨立資料隔離。

## Decisions

### 1. 獨立 SFTP 容器，而非 web 服務內嵌 sshd

- Rationale：web 鏡像是 Alpine + 單一 Go/http binary（見 `Dockerfile`）；內嵌 sshd 會混雜行程管理並擴大攻擊面。獨立容器可各自重啟、各自掛載旗標（web `:ro`、sftp `:rw`）。
- Alternative：在 web 鏡像加 `openssh` 並跑 supervisor —— 否決，理由同上。

### 2. 自建 Alpine + OpenSSH，支援運行期 user reconcile

- Rationale：`atmoz/sftp` 適合啟動時靜態宣告使用者，無法滿足 Admin UI 運行期開戶／停用。因此自建 `Dockerfile.sftp`，由 root entrypoint 執行 reconcile loop，再以 `exec sshd -D` 啟動 OpenSSH。
- `sshd_config` 固定關閉 `PasswordAuthentication`、`KbdInteractiveAuthentication`；使用 `ForceCommand internal-sftp`、`AllowGroups sftpusers`、`PermitTTY no`、`AllowTcpForwarding no`、`X11Forwarding no`、`PermitTunnel no`。authorized keys 使用 chroot 外的絕對路徑 `/etc/ssh/authorized_keys.d/%u`。
- Alternative：`atmoz/sftp` + 每次開戶重建容器 —— 否決，會中斷現有連線，且無法提供真正的運行期管理。

### 3. Root-owned chroot 與 share mount 佈局

SFTP 容器將同一 `${HOST_SHARE_PATH}` bind mount 到 `/share`，且以 `/share` 作為 `ChrootDirectory`。因 OpenSSH 要求 chroot 根目錄不可由 unprivileged user 寫入，部署前提是 Host 的 `${HOST_SHARE_PATH}` 本身為 `root:root`、mode `0755` 或更嚴格；只有 `${HOST_SHARE_PATH}/${SHARE_PREFIX}` 可寫。

預期佈局：

```text
/share                         root:root       0755   chroot root, not writable by SFTP users
/share/files                   root:sftpusers  2775   writable prefix (example SHARE_PREFIX=files)
/share/files/...               sftpuser:sftpusers, files 0664, dirs 0775
/etc/ssh/authorized_keys.d/*   root:sftpusers  0640   outside chroot, generated by reconcile; users read, never write
/var/lib/sftp-users/users.json root:root       0600   shared control-plane manifest; admin-only write
```

若既有 Host share root 不符合 root-owned chroot contract，部署必須先調整 Host ownership/mode；SFTP 容器不得為了啟動而任意 `chown -R` 使用者資料。

### 4. User manifest 與跨容器 reconcile

`sftp` 與 `sftp-admin` 共用 named volume `sftp-users`，掛載於 `/var/lib/sftp-users`。唯一跨容器控制面是 `users.json`：

```json
{
  "version": 1,
  "users": [
    {
      "username": "alice",
      "enabled": true,
      "authorized_keys": ["ssh-ed25519 AAAA... alice"]
    }
  ]
}
```

Admin UI 以 temporary file + `fsync`（可行時）+ atomic rename 寫入完整 manifest，並以 manifest-level lock 避免同時更新遺失。SFTP entrypoint 每 2 秒檢查檔案 mtime/digest；變更後驗證 JSON、username regex、保留名稱與 key 格式，然後：

1. 為 enabled user 建立本地 Linux user（`sftpusers` group、`/sbin/nologin`、無可寫 home）並生成 `/etc/ssh/authorized_keys.d/<username>`，mode `0640`、owner `root:sftpusers`；這是 OpenSSH 在本 Alpine 版本下可讀取且 SFTP user 不可寫入的最小權限。
2. 對 disabled user 移除 authorized key file，並停用或移除本地帳號；不影響其他 user。
3. 重新載入 key 不需要重啟 sshd；user/account reconciliation 若失敗，保留上一份有效 key state 並記錄錯誤。

這個設計讓 Admin UI 不需要、也不允許存取 SFTP 容器的 `/etc/passwd`、`/etc/ssh` 或 Host share。為確保 `users.json` 的 `0600 root:root` 權限，Admin container 的 manifest writer 以 container root 執行；這個 root 只可接觸它所掛載的 `sftp-users` volume，且不掛 Host share。SFTP container 對 manifest volume 使用 read-write mount 僅為了在首次啟動且檔案不存在時寫入 `SFTP_SEED_*`；正常 reconcile 不修改 manifest，Admin 仍是唯一的運行期管理者。

### 5. Permissions & Ownership

- Compose 中 web 使用 `${HOST_SHARE_PATH}:/opt/sharefiles:ro`，SFTP 使用 `${HOST_SHARE_PATH}:/share:rw`；兩者看到同一資料根。
- `SFTP_GID` 指定 `sftpusers` group 的固定 GID；Host 上的 `${SHARE_PREFIX}` 子目錄必須由相同 GID 可寫，並設定 setgid（`2775`）。
- `internal-sftp` 的 upload umask 設為 `0002`，使新 regular files 等價於 `0664`、directories 等價於 `0775`，讓 web 非 root process 可讀取／ traversable。
- 啟動檢查只驗證與報錯，不對既有資料遞迴改 ownership；既有檔案必須已符合 web read contract。
- 這是共用資料樹，不提供 per-user isolation；任何 enabled SFTP user 對可寫 prefix 的權限依該目錄 Unix mode 共享。

### 6. 認證與 seed

- `SFTP_ADMIN_PASSWORD` 只屬於 `sftp-admin`，缺少時僅 Admin container fail fast；SFTP container 不依賴它。
- 可選 `SFTP_SEED_USER` + `SFTP_SEED_PUBKEY` 僅在 `users.json` 尚不存在時建立第一個使用者；seed key 不覆蓋已有 manifest。
- SFTP 只接受 public key；Admin UI 產生的 key 與外部登記的 key 都落入同一 manifest。

### 7. Admin UI：獨立 Go 容器

- Rationale：repo 主語言是 Go（見 `internal/`），以 Go static binary + Alpine 可沿用現有建置流程，不新增 Python/Node 工具鏈。
- UI 只掛載 `sftp-users` volume，使用 `SFTP_ADMIN_PASSWORD`；預設 container listen `:8080`，Compose 預設只在 Host `127.0.0.1:${SFTP_ADMIN_PORT:-8081}` 發布。
- Session 使用隨機 opaque HttpOnly cookie、SameSite protection、30 分鐘上限與 logout；登入 password constant-time compare，失敗嘗試 rate-limit，mutation 需要 CSRF token。
- `ssh-keygen -t ed25519` 產生 keypair 時，private key 只在受保護的 temporary directory 短暫存在；單次 download response 後刪除，不寫入 manifest、persistent storage 或 log。生產環境需以 TLS 或 private network 保護 Admin UI。
- Alternative：Python + Flask —— 否決，新增工具鏈且與 repo 現況脫節。

## Risks / Trade-offs

- [Host root ownership 前提] 現有 `HOST_SHARE_PATH` 若不是 root-owned/non-writable，OpenSSH 不會接受 chroot → Mitigation：啟動檢查明確報錯，部署文件提供 ownership/mode 前置步驟。
- [Admin UI 成為特權入口] 可開戶即等同可寫入分享目錄 → Mitigation：localhost bind、強管理密碼、CSRF/rate limit，生產必須 TLS/private network。
- [Reconcile 暫時延遲] manifest 變更最多約 2 秒才反映 → Mitigation：UI 顯示 pending/reconciled 狀態；驗收允許明確的短時間窗口。
- [私鑰一次性顯示] 使用者若遺失只能 revoke 後重建 → Mitigation：下載頁明確提示備份；伺服器不提供 recovery。
- [可寫入導致連結漂移] SFTP 覆寫檔案後，`HASH_TARGET=file` 舊分享連結會失效 → Mitigation：README 說明並建議需要穩定檔名連結時使用 `filename` 模式。
- [uid/gid 權限錯位] Host share 的 group GID 若與 `SFTP_GID` 不一致，上傳會失敗 → Mitigation：啟動檢查 GID/mode 並提供明確錯誤。
- [sftp-users volume 遺失] 所有 SFTP users/keys 會消失 → Mitigation：文件提供 volume backup/restore；不可把 private keys 當作可恢復資料。

## Migration Plan

1. 新增 `Dockerfile.sftp`、`Dockerfile.sftp-admin`、user manifest schema、reconcile entrypoint 與最小 OpenSSH 設定。
2. 新增 Compose `sftp` + `sftp-admin`、共用 `sftp-users` volume；web 維持 `:ro`，SFTP 使用 `:rw`；補上 `SFTP_PORT`、`SFTP_ADMIN_PORT`、`SFTP_ADMIN_PASSWORD`、`SFTP_GID`、可選 `SFTP_SEED_*`。
3. 既有部署先確認 `${HOST_SHARE_PATH}` root ownership、`SHARE_PREFIX` group write/read permissions，再 `docker compose up -d`；既有 web links 不需變更。
4. `docker-compose.dev.yml` 以一次性 init service 將 repo-local fixture 複製到 root-owned `share-data` named volume；web 與 SFTP 共用該 volume，另掛測試 manifest、測試 key 與固定測試 admin password。測試 key/password 不得進 production image。
5. README 新增 SFTP/Admin 操作、TLS/private-network 警告、permissions 前置條件、私鑰一次性下載、hash link 漂移與 volume backup 說明。
6. Rollback：停止並移除 `sftp`、`sftp-admin` services 即可；保留 `sftp-users` volume 與 share data 以便恢復，web 服務與既有 links 不受影響。
